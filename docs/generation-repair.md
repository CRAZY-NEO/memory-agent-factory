# 生成与修复流程改进

> 当前默认 `spec`，完整模板不进入生成/审查/修复上下文；`reference` 为显式复刻模式。下方历史章节保留此前采用完整参考实现的改进和实验，不能作为当前无参考代码生成或历史经验提升的证据。新增业务契约、经验开关及对照实验见 [当前指南](spec-generation-and-experiments.md)。

## 当前标准 Factory 流程

Coder / Repairer 使用 `python_source_v1`，直接输出完整源码；其余结构化角色及来源评分函数角色仍返回 JSON。解码只接受原文或一个完整 Python 代码围栏，不改写代码。每次角色调用最多尝试两次，重试收到原响应和实际错误。日志保存原始响应、协议及解析结果，经验冻结工具按对应协议严格核验原文与产物；旧 JSON 记录不转换或覆盖。

被拒绝的源码保留供审计和修复，但不执行。Reviewer 的自由文本诊断保留在 `diagnosis.json`，不再作为 Repairer 指令；修复只接收可信执行诊断、静态发现、验证反馈和规格。有限修复优先保留已有实现并定点修改，无源码或上一轮实现仍未改变时才重建；最后一轮还会检查最近两次执行是否没有可观测验证进展。修复预算不变，第二次修复并非固定丢弃已有代码。

分类接口明确 `texts` 为字符串列表、`training_examples` 为字典列表，按 `text` / `label` 键取值；`enabled` 缺省表示启用。分类规格明确字符 TF-IDF 的 `analyzer="char"` 与 `ngram_range=(1, 3)`，并区分估计器参数：`random_state=42` 用于 LogisticRegression，不用于 TfidfVectorizer 或 MultinomialNB。组合预处理依照契约依赖执行，先过滤禁用训练行，再对有效行按精确 `(text, label)` 去重；预测文本的空白项、顺序和重复位置都须保留。

验证反馈保留失败的 case / contract ID，仅合并完全重复的错误，不再只取前 12 条错误或前 6 项执行诊断。分类的空白输入、单标签、空词表、输出长度等基础失败会映射为 `failed_base_behaviors`：内容是既有公共契约及实际失败来源，帮助 Repairer 同时处理基础边界与新增要求。单标签异常中的具体训练标签会脱敏；探针输入、预期标签和逐条预测仍不进入反馈。Reviewer 的自由建议继续隔离，这些修复目标不从其诊断中提取。

若 Repairer 返回与失败版本 AST 相同的源码，当前响应立即记为无进展，不再把同一源码重复放进第二次响应请求；剩余算法修复轮次按原预算重建。重建前会核验本轮同候选旧版本的文件哈希和 AST，仅在实现一致时恢复其可信运行错误及需求检查，记录 `feedback_origin`。只有源码字节相同才保留旧报错行号；仅 AST 相同时移除旧位置。原拒绝报告仍为 `executed=false`，不会将旧执行冒充本次执行，也不引用最终测试或其他候选的反馈。

定点修复的实际消息按“任务规格 → 模型上一版源码 → 本轮可信失败反馈”排列，末条请求明确要求修复失败行为并保留已通过行为。定点修复与重建都会去除诊断和验证对象中的相同副本；重复错误按完整消息分组，保留全部来源 ID 和原顺序，重复执行诊断还保留各 case 的次数与源码位置。只有分组更短时才使用它。进展和来源记录只向模型发送原因与来源说明，完整哈希、比较依据和未压缩反馈仍保存在原始 `context`；日志另存实际 `messages`。旧源码、新响应和失败行为要求均不被改写。这是提示组织改进，不构成成功率提升的证据。

新增需求检查会保留失败探针的公共 case ID、异常类别和生成源码行号；单类别和空词表异常转换成固定的公共描述。原始异常可能包含私有输入，不直接转发；探针内容、预期答案及局部变量不会进入修复上下文。只有实际发生的异常才产生执行诊断，单纯结果不符不会虚构堆栈。

最后允许的修复轮还检查同候选最近两版的执行报告：代码文件哈希可信、失败错误集合与需求检查集合相同、且质量指标没有改善时，记录 `no_observable_progress` 并转为重建。缺少可核验的执行证据、错误已经变化或质量指标改善时不触发；运行耗时波动不作为算法质量改善。该判断不证明两版程序语义等价，也不扩大修复预算。报告记录参与比较的实现 ID、修订号及源码哈希。

Ollama 请求的上下文容量由 `OLLAMA_NUM_CTX` 设置，默认 8192，最小 1024；内存有限的设备可使用 4096。实际容量写入每次调用的 `options.num_ctx`，日志记录实际消息字符数以及服务返回的输入、缓存和输出 token 计数。字符数不是 token 数；仅凭 `done_reason=stop` 或单个输入计数，不能确认上下文未发生截断。更改上下文是新的实验条件，应保留旧运行并核查实际输入／输出 token、结束原因和服务错误；它不能保证生成代码正确。

Coder / Repairer 的连接或模型服务故障耗尽响应重试后停止，不再继续调用 Reviewer / Repairer。报告使用 `failed_generation` 区分生成阶段失败与算法检查的 `failed_validation`；拒绝源码的验证记录标明 `executed=false`。响应修复、源码变化、框架测试通过都不等于算法验收通过，仍须满足全部门禁与独立最终测试。

## 2026-10-13 旧版：具体改动

1. **算法专属上下文**：Coder、Reviewer、Repairer 只读取当前能力、对应原文、插件指导与参考实现。规划仍读取全部相关知识；未经验证的旧建议不会当成代码指令。
2. **可信报错定位**：执行器输出生成文件的函数名、行号与实际源码行；验证器归并重复异常，保留触发次数。反馈不带宿主文件路径、局部变量或相关文档标注。
3. **审查模型参考依据**：Reviewer 同时看到参考实现、实际失败代码、错误行及简单静态发现，优先解释实际异常，不能将错误类型改写成未发生的异常。
4. **两种修复策略**：第一次定点修复，第二次从参考示例重新复刻。第二次不再传入错误代码全文，降低原实现的影响；错误事实和源代码哈希仍保留。
5. **修复进展检查**：AST 指纹忽略注释和文档字符串。如果修复返回同一结构，报告明确标记 unchanged 并拒绝作为成功修复。指纹不等于一般意义的行为等价证明；其他无关改动仍须靠实际验证发现。
6. **公开算法契约**：插件可声明 `public_cases`，验证具体评分公式，而不只检查接口。Jaccard 的公开例子中，“甲乙”与“乙丙”的单字/双字集合相似度为 0.2；TF-IDF 公开小语料检查整篇文档与评分的对应关系。另用 ALPHA、alpha 和 beta 检查英文整词与大小写规则，拒绝把英文拆成字母的实现。例子公开提供给模型，独立最终测试依旧不进入提示。
7. **历史失败重放**：`--repair-from` 读取选择的运行目录，核验旧代码哈希，取启用算法中最后一个仍失败的修订重新执行，再进入真正的审查/修复循环。重放 r0 在报告中明确标为 historical_replay，不记作本次模型生成；已通过的旧候选不重放。

真实模型模式下，每次新生成或修复都以模型返回的完整代码为准，验证器不会把无效响应替换成参考文件。接口、指标门槛、修复上限和最终测试隔离保持原规则。执行器源码哈希也进入新运行环境记录。

## 历史重放命令

```bash
cd ~/Downloads/agent-factory
# 修改执行器后须更新 Docker 镜像
docker build -f Dockerfile.runner -t agent-factory-runner:0.1 .
# 保持 SSH 隧道，重放上次真实失败代码并让模型修复
FACTORY_PROVIDER=ollama FACTORY_DEMO_WORKSPACE=state/repair-ollama-demo \
OLLAMA_URL=http://127.0.0.1:11435 OLLAMA_CHAT_MODEL=qwen3.5:2b \
bash scripts/run_plugin_demo.sh --repair-from examples/plugin-ollama-demo
# 常规新生成仍使用原命令，不需要历史重放
FACTORY_PROVIDER=ollama FACTORY_DEMO_WORKSPACE=state/focused-generation \
bash scripts/run_plugin_demo.sh

bash scripts/run_tests.sh -q
```

`--repair-from` 是本地 CLI 的显式历史复验，不是中断恢复或 checkpoint。若故意修改历史代码，哈希不符会停止。不要将历史真实重放与 mock `--inject-fault` 合用。

新增测试覆盖旧异常的源码定位、算法专属提示、无效修复与重新复刻、历史代码防篡改、实际重放修复、错误公式和英文拆字拒绝；该次改进时自动测试共 50 项通过，当前测试规模见 README。

以下命令在当前版本上使用当前响应协议和修复策略，不会逐字重现旧版模型输出；旧版证据以归档调用记录为准。

## 自动路由验收发现的边界

真实验收中，Router 曾因 BM25Plus 不在目录而返回空方法列表。现增加有限的原文方法名提取，保留模型原判断，并禁止将 BM25Plus 匹配成 BM25。指定的新方法提议也必须匹配请求名称。

混合需求曾使通用 query/index 函数挤占来源上下文，遗漏构造默认参数；业务指标通过仍可能产生错误评分公式。现优先保留目标评分核与构造函数，标量 TF/IDF 路径无法建立数值契约时停止登记。此前测试目录中的错误登记已撤销，原始报告和源码复核记录保留。

当时的真实模型偶尔在 JSON `code` 字段重复转义换行、漏闭合引号或返回不完整源码。响应接收时加入 AST 语法检查，消耗已有的一次响应重试，不直接修改代码、不使用模板替换。当前标准 Coder / Repairer 已改用前述源码协议；来源评分函数仍采用 JSON。两条路径在合法语法之后都须通过安全、接口、公式、指标与运行检查。详见 [自动路由](automatic-routing.md)。
