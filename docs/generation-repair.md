# 生成与修复流程改进

## 已确认的失败原因

旧三算法真实运行 `20261013T172815_22ac726c` 保存在 `examples/plugin-ollama-demo/`，不覆盖原始证据。

| 算法 | 代码错误 | 为什么修复无效 |
| --- | --- | --- |
| TF-IDF | `doc_tokens.extend(text.lower().split())` 将完整文档拆成词，去重词列表用于 fit_transform；每行评分随后按 `memories[i]` 取 ID，行数与记忆数不一致导致 IndexError；英文清洗也移除了中文查询 | Reviewer 把 IndexError 错诊为向量器的 ValueError，建议清洗空文档；r0/r1/r2 文件 SHA-256 完全相同，前缀都是 `3706924caa63`，实际没有修复 |
| Jaccard | 中文片段先转成 set，再执行 `chinese_chars[i:i+2]`，集合不支持切片；片段与单字/双字的层次也混淆 | Reviewer 将合法的 `&`/`|` 改为方法调用，或建议改变 ID 大小写，没有修正报错的分词行；后续只是改写注释及其他无关部分 |

旧生成提示带入三种算法材料和历史，修复时又包含完整验证对象。日志中生成输入约 5500～5800 token、修复约 6860～6950 token，上下文预算 8192。无关信息增加理解负担；没有证据证明这次输入已被截断。模型参数量、提示长度的因果影响仍需额外对照实验，不能仅凭这一次运行断言。

## 具体改动

1. **算法专属上下文**：Coder、Reviewer、Repairer 只读取当前能力、对应原文、插件指导与参考实现。规划仍读取全部相关知识；未经验证的旧建议不会当成代码指令。
2. **可信报错定位**：执行器输出生成文件的函数名、行号与实际源码行；验证器归并重复异常，保留触发次数。反馈不带宿主文件路径、局部变量或相关文档标注。
3. **审查模型参考依据**：Reviewer 同时看到参考实现、实际失败代码、错误行及简单静态发现，优先解释实际异常，不能将错误类型改写成未发生的异常。
4. **两种修复策略**：第一次定点修复，第二次从参考示例重新复刻。第二次不再传入错误代码全文，降低原实现的影响；错误事实和源代码哈希仍保留。
5. **修复进展检查**：AST 指纹忽略注释和文档字符串。如果修复返回同一结构，报告明确标记 unchanged 并拒绝作为成功修复。指纹不等于一般意义的行为等价证明；其他无关改动仍须靠实际验证发现。
6. **公开算法契约**：插件可声明 `public_cases`，验证具体评分公式，而不只检查接口。Jaccard 的公开例子中，“甲乙”与“乙丙”的单字/双字集合相似度为 0.2；TF-IDF 公开小语料检查整篇文档与评分的对应关系。另用 ALPHA、alpha 和 beta 检查英文整词与大小写规则，拒绝把英文拆成字母的实现。例子公开提供给模型，独立最终测试依旧不进入提示。
7. **历史失败重放**：`--repair-from` 读取选择的运行目录，核验旧代码哈希，取启用算法中最后一个仍失败的修订重新执行，再进入真正的审查/修复循环。重放 r0 在报告中明确标为 historical_replay，不记作本次模型生成；已通过的旧候选不重放。

真实模型模式下，每次新生成或修复都以模型返回的完整代码为准，验证器不会把无效响应替换成参考文件。接口、指标门槛、修复上限和最终测试隔离保持原规则。执行器源码哈希也进入新运行环境记录。

```bash

# 常规新生成仍使用原命令，不需要历史重放
```

`--repair-from` 是本地 CLI 的显式历史复验，不是中断恢复或 checkpoint。若故意修改历史代码，哈希不符会停止。不要将历史真实重放与 mock `--inject-fault` 合用。

新增测试覆盖旧异常的源码定位、算法专属提示、无效修复与重新复刻、历史代码防篡改、实际重放修复、错误公式和英文拆字拒绝；该次改进时自动测试共 50 项通过，当前测试规模见 README。

## 自动路由验收发现的边界

真实验收中，Router 曾因 BM25Plus 不在目录而返回空方法列表。现增加有限的原文方法名提取，保留模型原判断，并禁止将 BM25Plus 匹配成 BM25。指定的新方法提议也必须匹配请求名称。

混合需求曾使通用 query/index 函数挤占来源上下文，遗漏构造默认参数；业务指标通过仍可能产生错误评分公式。现优先保留目标评分核与构造函数，标量 TF/IDF 路径无法建立数值契约时停止登记。此前测试目录中的错误登记已撤销，原始报告和源码复核记录保留。

真实模型偶尔在 code 字段重复转义换行、漏闭合引号或返回不完整源码。响应接收时先做 AST 语法检查，消耗已有的一次响应重试，不直接修改代码、不使用模板替换。合法语法之后仍需通过安全、接口、公式、指标与运行检查。详见 [自动路由](automatic-routing.md)。
