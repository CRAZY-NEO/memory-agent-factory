# 通用候选生成与修复实验：词频统计和文本去重

2026-10-17，使用真实 DeepSeek `deepseek-v4-pro` 和 Docker，验证两个未登记的新任务能否复用同一生成、检查和修复流程。最终两项均通过；此前四轮工程运行中发现的失败保留在[全部尝试汇总](../examples/generic-draft-experiments/summary.json)，不能把最后一轮解释为一般成功率。

## 相比原系统改变了什么

原有检索、分类和文档审查依赖已登记的任务契约与领域评估器。现在遇到新任务，系统可以继续搜索组件库/GitHub，提出 JSON 输入输出规格，审查示例一致性，生成组件，隔离执行并根据具体差异修复，不必先增加该任务的专用模板或适配器。本次没有注册词频统计、文本去重的生产算法或可信评分器。

这是任务接入与验证组织方式的扩展，不是模型算法能力已普遍提高的证明。新任务仍交付待业务验证候选；四类已有任务的可信认证、复用、更新、回归和版本回退继续保留。

## 实验设计

- 词频统计：仅匹配连续 ASCII 字母，统一小写，次数降序，同频按词升序。数字、中文、下划线、撇号等是分隔符。
- 文本去重：用 `strip().casefold()` 作键，排除空白项，保留第一条原始字符串及首次出现顺序，不合并内部空白或做 Unicode 规范化。
- 两项都通过 `ComponentService.ensure` 的真实路由进入现有 `DraftFactory`，接口均为 `execute(payload) -> dict`。自然生成使用各自新工作区，不读取已经生成的本任务答案。
- [协议与人工期望](../examples/generic-draft-experiments/protocol.json)在首次 API 调用前固定，每任务 16 条。模型不接收这些人工期望；生成后从候选 ZIP 取出源码，在 Docker 中逐项精确比较输出并检查输入不变。
- 自然生成若首版通过，不伪称发生过代码修复。另建明确标记的受控故障实验，在真实源码副本中注入错误，冻结原规格，由真实 Repairer 修复；原成功产物保持不变。

模型会接收公网静态抽取的限长函数片段及许可，它们是未验证参考。本实验没有新增本地完整模板，但也不是严格“不给任何代码参考”的实验，更不是算法原创性实验。没有执行外部仓库代码或自动安装其依赖；搜索结果相关性仍可能不足，搜索成功不等于已复刻该仓库算法。

## 最终结果

| 新任务 | 规格审查 | 自然生成的代码 | 人工验收 | 单独的故障与修复 | 修复后人工复验 |
| --- | --- | --- | --- | --- | --- |
| 英文词频统计 | 首版一致 | r0 通过，4 个提议示例 | 16/16 | 注入每词计数 +1，3 个提议示例失败；一次真实修复通过 | 16/16 |
| 文本列表去重 | 首版有错，自动重新规划一次后通过 | r0 通过，4 个提议示例 | 16/16 | 注入结果顺序反转，2 个提议示例失败；一次真实修复通过 | 16/16 |

共 32 个不同人工用例，覆盖空输入、排序、标点、数字切分、中英文混合、Unicode、重复项、原文保留、内部空白及输入不变。修复后复用了同一组用例，不能算成 64 个独立测试样本。人工验收结果没有回流本轮生成或修复，受控返修只使用已冻结的模型提议示例及实际执行差异。

最终一轮共 **12 次真实 HTTP 模型调用**：词频自然流程 4 次、故障修复 1 次；去重自然流程 6 次、故障修复 1 次。另有 1 次历史错误规格复查。故障实验的规划、规格审查和首版错误代码是明确重放的实验输入，不计为新模型调用。

四份交付源码均逐字对应最后一次真实模型响应，并核对 ZIP 中源码与封存文件哈希。每项的自然生成和返修都实际执行了 Docker 检查。最终运行期间工厂源码未改变。候选记录回写知识库，批准版本和启用绑定均为 0，`business_verified=false`。

## 实验发现的问题及通用修正

1. **路由只按“去重”关键词匹配，误选检索任务。** 路由现在接收完整输入输出契约；只匹配附加规则但没有基础任务时进入候选生成，不擅自补成检索任务。普通的 `execute(payload)`、`text.strip()` 调用也不再被识别成算法名称。
2. **规划者可能写错自己的示例，正确代码被错误测试拒绝。** 例如把 `Straße` 和 `STRASSE` 当作不同键，或忽略内部空白差异。新审查角色看不到规划者的期望和生成代码，先从需求及示例输入推导结果，再由程序比较；分歧在冻结之前交回 Planner。最多重新规划两次，仍不一致则停止生成，不能改代码迎合有争议的期望。
3. **非思考模式的审查也会算错，或直接认可错误示例。** 为通用路由、规划和审查增加独立配置 `DEEPSEEK_PLANNING_THINKING=enabled`；代码生成和修复仍遵循 `DEEPSEEK_THINKING`，本次为 disabled。实际配置保存在每次调用日志中。最终文本去重确实发生了一次规格纠偏；[历史错误规格复查](../examples/generic-draft-experiments/known-bad-spec-recheck.json)也重新识别出两处原有矛盾。
4. **错误反馈过于笼统、返修可能原样重复。** 反馈给出 case ID、输入、期望、实际、第一处结构差异及已通过案例。AST 指纹识别仅改注释/空行的重复失败，下一轮切换为从冻结规格重建；页面区分规格矛盾、执行失败和示例不符。

前四轮状态分别是：路由拦截去重；错误示例导致返修失败；仅“同意/不同意”的审查漏检；非思考的独立推导仍出现错误。它们都在汇总和失败报告中保留。多项工程修正及推理配置同时变化，因此本实验不是对某项改动的单变量消融，不能据此量化其独立收益，也没有新增历史经验开关的因果结论。

## 可以证明与尚不能证明的部分

这两个新任务已经通过同一套通用 JSON 执行和有限修复流程，不需要为每个任务再编写一套工作流。人工提供的输入和期望也能由同一精确比较器执行。

但审查者与规划者仍使用同一模型，可能共同犯错；系统无法仅凭自身示例证明任意业务正确性。此次人工用例是实验中的独立验收证据，**不会自动成为生产可信验证器，也不会自动启用候选**。当前通用环境仅覆盖受限、无副作用的纯 Python JSON 处理，不保证网络服务、数据库修改、复杂依赖、语义判断或任意软件项目。外部业务系统联调尚未进行。
