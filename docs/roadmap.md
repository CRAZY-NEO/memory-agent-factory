# 剩余功能与补齐优先级

核心“理解—抽取/检索—规划—生成—验证—修复—回写”已实现。CLI 与 API、候选比较、插件注册、图谱导出、报告、版本和失败经验也已实现。GitHub 远端尚未配置，需要使用项目所有者的实际仓库地址。

以下时间是基于现有代码、单人熟悉 Python 的粗略估计，不包含真实业务数据标注等待。

| 优先级 | 可补齐的功能 | 现有基础与最小实现范围 | 估计 |
| --- | --- | --- | --- |
| 1 | 更可信的行业评估集 | 扩大技术笔记、加入同义改写、相近负例和多相关文档查询；分离验证与全新最终测试，报告补充逐查询失败归类 | 半天～1 天，取决于标注量 |
| 2 | 简单 Web 操作界面 | 现有 FastAPI/异步任务 API 上加静态 HTML：提交描述、轮询进度、显示候选指标、查看报告和产物；无需重建后端 | 半天～1 天 |
| 3 | 能力与代码版本对比 | 已保存修订、代码哈希和验证结果；增加列表与两个版本的代码/指标对比视图，显示能力来源 | 半天 |

Web 界面属于体验增强，当前 CLI/API 已满足笔试“界面、CLI 或 API”的要求。版本存储和依赖/部署配置已有基础，不应把它们整体描述为未实现；缺的是对比视图和产物打包体验。现有 FastAPI 默认已经提供 /docs 和 /openapi.json，自动接口文档不是缺项。

## 工作量较大的方向

- 真正中断恢复：需要 checkpoint、执行阶段幂等、代码文件与数据库事务一致性；历史失败重放不能替代它。
- 跨任务类型迁移：当前仅 memory_retrieval，文本分类需要独立数据契约、训练/测试隔离、指标和执行环境。
- Beam Search/MCTS：需要定义有意义的方案状态、动作、代价与搜索预算，不能只是把现有候选循环改个名字。
- 自治多 Agent 工具协作：当前角色由同一模型串行承担，加入工具权限、消息协调和冲突解决比多个 prompt 更复杂。
- 持久索引与大语料优化：现接口每次检索重建统计量；build_index/search 会影响产物、资源评估与版本生命周期。

先补评估数据和 Web 演示，再考虑 AST 仓库抽取，通常更有助于展示质量与加分点。当前不建议为了覆盖所有加分项同时扩展多个任务和搜索框架。
