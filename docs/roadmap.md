## 工作量较大的方向

- 真正中断恢复：需要 checkpoint、执行阶段幂等、代码文件与数据库事务一致性；历史失败重放不能替代它。
- 跨任务类型迁移：当前仅 memory_retrieval，文本分类需要独立数据契约、训练/测试隔离、指标和执行环境。
- Beam Search/MCTS：需要定义有意义的方案状态、动作、代价与搜索预算，不能只是把现有候选循环改个名字。
- 自治多 Agent 工具协作：当前角色由同一模型串行承担，加入工具权限、消息协调和冲突解决比多个 prompt 更复杂。
- 持久索引与大语料优化：现接口每次检索重建统计量；build_index/search 会影响产物、资源评估与版本生命周期。

下一步可做版本对比或 AST 仓库抽取；评估数据还需要业务专家审核、无答案与更大语料。当前不建议为了覆盖所有加分项同时扩展多个任务和搜索框架。
