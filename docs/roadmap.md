## 工作量较大的方向

- 真正中断恢复：需要 checkpoint、执行阶段幂等、代码文件与数据库事务一致性；历史失败重放不能替代它。
- 跨任务类型迁移：当前仅 memory_retrieval，文本分类需要独立数据契约、训练/测试隔离、指标和执行环境。
- Beam Search/MCTS：需要定义有意义的方案状态、动作、代价与搜索预算，不能只是把现有候选循环改个名字。
- 自治多 Agent 工具协作：当前角色由同一模型串行承担，加入工具权限、消息协调和冲突解决比多个 prompt 更复杂。
- 持久索引与大语料优化：现接口每次检索重建统计量；build_index/search 会影响产物、资源评估与版本生命周期。

AST 仓库抽取已实现，见 [仓库指南](repository-extraction.md)；候选始终为静态未验证证据。v2 新数据已完成 qwen3.5:2b 真实全流程，见 [报告](../examples/ollama-v2-demo/report.md)。新增 [GitHub Actions](ci.md) 检查代码、测试、包装资源及 AST + Docker 离线闭环。

GitHub 自动寻找公开算法仓库、固定提交下载、源码适配及验证后登记也已实现，见 [发现指南](github-discovery.md)。它扩展当前检索场景的方法来源；跨任务契约、数学等价性自动认证、任意依赖自动部署仍属于后续工作。
