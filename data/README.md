## 查询类型与标注

| category | 验证数 | 最终测试数 | 含义 |
| --- | --- | --- | --- |
| direct | 12 | 6 | 保留关键术语的词面基线 |
| paraphrase | 8 | 8 | 用不同表述描述同一问题，保留必要业务实体 |
| hard_negative | 8 | 8 | 同产品或近似术语，但需要区分故障、操作或评价对象 |
| multi_relevance | 8 | 8 | 显式询问多项问题，标注全部直接答案 |

relevant_ids 是直接回答问题的记忆；hard_negative_ids 是容易误召回但不能直接回答的记忆；两者必须不相交，所有 ID 必须存在且不重复。annotation 解释标注理由。category 表示主要测试的能力；改写与多相关查询也可带负例。

例如 v22 询问 Redis **一个热点 key 过期**：m28（击穿）相关，m03（穿透）、m04（多键雪崩）、m27（未过期热键）是相近负例。v35 同时询问 API 超时重试与日志密钥保护，m18、m17 都相关。

负例位于同一个完整语料内，不是另外传给算法的“排除名单”。执行器只收到 query/memories/top_k，标注只留在可信评分器。未知字段、不存在 ID、重复标签和正负重叠均会在运行前拒绝。

## 验证与报告

总体指标仍按 config.json 原阈值验收，没有因扩充数据降低门槛。报告额外给出各类型指标、漏召回 ID、首个相关排名、相近负例命中及负例排在所有相关答案之前的情况。

failure_count 包括漏召回、首个相关结果未排第一或负例优先。一份总体通过的报告仍可包含失败查询；分组指标和负例分析目前是诊断项，不是独立门槛。多相关查询采用二元相关性，相关文档的顺序不要求固定。

所有 v2 最终测试查询在本次评估前固定，与验证集及 v1 最终查询无完全相同的文本。共享领域和语料是有意的，不宣称领域外泛化或严格语义独立。生成/修复不读取验证或最终查询全文与标签；候选选择用总体验证指标，只有冻结的选定代码接受最终测试。

后续若利用最终结果调参，应另建新测试集。当前全部查询有答案，不覆盖无答案拒答、等级相关性、大语料或真实交互；这些需要独立的数据与指标契约。

## 重建与版本

```bash
.venv/bin/python scripts/create_demo_data.py
# 独立输出，不修改当前数据
.venv/bin/python scripts/create_demo_data.py --output /tmp/agent-factory-data-v2
```

脚本无需模型或网络，确定性输出三份数据及 dataset.json。v1 保存在 [examples/datasets/v1](../examples/datasets/v1/)，历史报告继续描述 v1，不套用新分数。每次运行继续记录实际数据 SHA-256。
